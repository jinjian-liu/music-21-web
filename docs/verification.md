## 测试方式与边界

API 集成使用 PGlite 执行 PostgreSQL SQL，S3 使用内存对象测试替身；不是纯路由 mock，但不等同于真实 PostgreSQL 16 网络服务、多数据库连接争抢或云存储网络测试。

浏览器测试将 API 不可用作为本地优先场景；云端成功路径由 API 集成覆盖。没有声称完成真实浏览器 → 网络 API → MinIO 的全链路部署验收。

当前机器没有 Docker，未运行 Docker Compose。未向公网发布。当前浏览器自动测试使用 Chromium，不代表 Safari、iOS 与所有触屏设备均已验证。麦克风实物演奏的音准、延迟和噪声表现仍需实际钢琴／小提琴验证。

## 目标环境验收

1. 按部署文档启动真实 PostgreSQL、MinIO、API、两个 Worker 与 Web。
2. 同时上传多个有效／损坏 MIDI，检查每个任务只产生一次提交，中止正在解析的 Worker 后确认租约恢复。
3. 验证 S3_PUBLIC_ENDPOINT 可从浏览器访问、签名有效、桶私有、CORS 正确。
4. 从第二个浏览器登录读取私人曲目，再完整走一遍提交、批准、举报、下架。
5. 使用实际麦克风检查权限、暂停、切页、后台和恢复；验证音轨播放、变速、循环以及触屏演奏。
6. 用升级前数据库备份在隔离环境运行增量迁移，并抽查旧分享链接和密码登录。

极端进程终止可能留下未引用的解析对象；运维需按部署文档检查孤立对象。自动测试不模拟浏览器进程被强制杀死时正在进行的最后一次 IndexedDB 写入。
