# 弦知平台实现说明

## 交互结构

主导航为概览、我的曲库、发现曲目、练习记录和练习工具。账号入口固定在导航区；管理员在同一区域看到内容管理入口。工作台独立于主布局，减少练琴时的干扰。

视觉使用暖白、低饱和绿色、浅灰绿层次；共享组件负责标题、按钮、提示、空状态、分页和原生 dialog 模态对话框。dialog 支持焦点约束、Esc 关闭及关闭后焦点恢复。焦点轮廓、足够大的控件、减少动画样式和移动端音轨展开入口统一实现。音符快捷键避开输入、可编辑区域及对话框；按钮和链接聚焦时保留空格键的原生操作。

概览使用本机真实数据。课程体系、AI 教学、自动生成课程、复音评分、社交关系和付费功能不属于本次实现。没有课程或连胜假数据。

## 本地与账号数据

IndexedDB 数据库 xianzhi-platform v1 包含 pieces、sessions、settings。pieces 保留原始 Blob、完整 ParsedSong、稳定本地 ID、云端 ID 和云端归属账号；不使用云端 ID 覆盖本地 ID。

导入立即解析并保存；只有 IndexedDB 事务完成才进入工作台。云端保存先确认账号，再按 owner + clientId 创建幂等上传意图。上传中断可再次保存，云端解析失败可重试。重复操作不创建重复曲目。换账号后可以将同一本机曲目主动保存到新账号。

旧曲目保留的浏览器解析内容可以迁入；旧版本没有原始 MIDI 的曲目不能凭空恢复原文件，首次上传需要重新导入。旧云端 UUID 仍可从对应账号读取。完全离线启动网站的 PWA 缓存不在本次实现范围；这里的“本地优先”指应用已加载时核心功能不依赖 API。

工作台按路由键重新挂载，避免切歌残留状态；私人 UUID 从账号接口读取，公开 slug 从公开接口读取；管理预览走管理员接口。声音偏好与工作台速度、唱名、循环和键盘展开状态保存在本机。

## 练习会话

PracticeClock 将一段会话的 wall-clock 开始／结束时间与有效时长分开。开始时分配 UUID；暂停累计有效时长，再次继续不重置起点；结束时清空时钟，同一个会话只形成一次记录。

只有练习模式启动音频或单音检测成功后才开始计时。切换目标、切换为听奏、自然结束或离开页面会结束当前会话；后台页面暂停。普通自动演奏不生成练习历史。历史会话 matched 与 attempted 留空，因为当前音符命中反馈不足以代表完整评分。

云端会话以 (user_id,id) 为主键，批量导入使用冲突忽略，不覆盖既有会话。用户主动保存全部本机记录到当前账号，每批最多 100 条。云端不上传录音。

## 曲目状态与权限

解析：uploading → queued → processing → ready；失败自动最多尝试三次，进入 failed 后可由所有者主动重试。

公开状态：private → pending_review → published/rejected；rejected 可修订重提；published 的信息修改重新进入 pending_review；管理员可以将 published 下架为 removed。下架不能由所有者直接再次公开。

审核检查解析已就绪、权利已确认、来源说明非空且授权未过期。每次审核锁定曲目行，修改状态和写审计记录在同一事务完成。举报处理也写入审计记录。公开读取与列表统一排除删除、非公开、未就绪或授权已过期的曲目。

旧 status 字段保留作为兼容读数；新逻辑以 parse_status/publication_status 为准。存储的 ParsedSong 格式仍为 v1；读取时覆盖曲名与状态，避免解析产物中的过期元信息影响界面。

## 后端任务与边界

API 负责 HTTP、身份校验和业务入口；Worker 单独启动。任务使用 FOR UPDATE SKIP LOCKED 原子领取，locked_at 为五分钟租约，lock_token 防止旧任务提交结果；工作期间每三十秒续约。超时处理中任务可被重新领取，崩溃尝试计入三次上限。

每次解析使用独立结果对象键，只有仍持有租约且曲目未删除时才提交结果，避免旧 Worker 覆盖新结果。失败会尝试删除未提交产物。对象存储和 PostgreSQL 不具备跨系统事务；极端进程终止仍可能留下未引用的解析对象，需要运维定期检查孤立对象。

删除先做数据库软删除和清理队列写入，立即禁止访问。原上传签名最长十分钟，所以清理延迟十一分钟以避免签名仍有效时文件被重新上传。清理失败每五分钟重试，按队列记录错误。下架仅关闭访问，保留源文件供复核。

API 错误经过统一转换。身份使用随机 HttpOnly Cookie 与数据库中的 SHA-256 令牌哈希；生产 Cookie 为 Secure。变更请求检查 Origin，查询过滤资源归属，管理员入口检查角色，接口有基础进程内限流。单机部署适用；多 API 副本应在共同网关实施共享限流。

## 实施后续

正式服务器启用前，需要真实 S3 签名／CORS、两个独立 Worker、实际麦克风与 Safari/iOS 的设备验收。已有数据库不要重建，通过迁移命令增量升级。不要仅将旧前端替换后继续运行旧 API；新版状态规则需要同时更新 API 与 Worker。
